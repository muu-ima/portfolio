# us-duty-profit-sheet

## Overview

us-duty-profit-sheet は、eBay US販売向けに、売値、仕入れ、送料、為替、HTSコード、原産国、関税、販売手数料をまとめて利益判断するための Google Sheets ベースの計算シートです。

単純に売値から仕入れを引くだけではなく、US販売で見落としやすい関税、MPF、Disbursement、カテゴリ手数料、決済手数料、Payoneer 手数料、両替手数料まで含めて、最終利益と利益率を確認できるようにしています。

シートは複数タブに分かれており、入力、計算ロジック、税率設定、HTSコード、原産国、カテゴリ手数料、PolicyBand が連動します。見た目はスプレッドシートですが、役割としては「入力フォーム、参照マスタ、計算エンジン、結果ダッシュボード」を組み合わせた小さな業務ツールに近いです。

## Background

海外販売では、商品価格と送料だけを見ても実際の採算が分かりません。

特に US 向け販売では、品目ごとの HTS コード、原産国、追加関税、申告額、MPF、Disbursement、販売カテゴリごとの手数料が重なります。さらに、売値は USD、仕入れや送料は JPY で見るため、為替と両替手数料も利益に影響します。

このシートでは、そうした判断材料をひとつの入力シートに集めつつ、税率や手数料の前提は別タブのマスタとして分けています。手作業で計算するたびに前提がぶれないよう、参照元と計算結果を分けることを重視しています。

## Sheet Structure

### 入力シート

日常的に触る入口です。

USDJPY、仕入れ、売値、送料、原産国、HTSコード、カテゴリ手数料などを入力し、最終利益、利益率、関税内訳、VeRO 関連の比較値を確認します。

入力シートは、利用者が判断するための画面として使います。裏側の税率や手数料表を直接触らなくても、販売前に採算を見られる構成です。

### ロジック

計算の中心になるタブです。

eBay US販売ロジック、関税計算、VeRO補正計算をまとめています。売上、州税、カテゴリ手数料、決済手数料、Final Value Fee、手数料TAX、Payoneer 手数料、両替手数料、送料、税還付、最終利益、利益率などを段階的に計算します。

関税計算側では、送料USD、売値+送料USD、関税率、安全側仮関税USD、PolicyBand、申告売値、申告合計、関税USD、関税JPY、MPF、Disbursement、関税+手数料合計を扱います。

### 関税設定

入力された原産国と HTS コードから、最終的に使う関税率を合成するための設定タブです。

原産国税率、HTS基礎関税、301条、232条、原産国税率免除フラグ、その他追加税率を分け、関税率の合成値を作ります。たとえば中国製品では、原産国税率と301条追加関税が重なり、合成関税率が大きくなります。

### PolicyBands

安全側仮関税USDから、採用する PolicyBand を決めるためのタブです。

計算された関税見積もりをそのまま使うのではなく、7、15、30、55、80、110、180 のような帯に当てはめ、上側Band、下側Band、採用Bandを出します。販売判断や申告額の見積もりを安全側に寄せるための補助ロジックです。

### カテゴリ手数料

eBayカテゴリごとの販売手数料率マスタです。

ギター・ベース、PC機器、ゲーム機本体、カメラ・レンズ、スマホ、タブレット、トレカ、時計、書籍・映画・音楽など、カテゴリごとに異なる fee percent を持たせています。

入力シートでカテゴリを選ぶことで、ロジック側のカテゴリ手数料率に反映されます。

### HTSコード

品目ごとの HTS コードと税率を管理するマスタです。

HSコード、HTSコード、品目、基礎関税、301条、232条、232条免除、その他追加、合算税率を持ちます。タオル、玩具、ビデオゲーム機、筆、傘、手袋、楽器、ガラス、食器、衣類、調理機器、デジタルカメラ、カメラレンズなど、販売候補の商品に合わせた品目を登録しています。

HTSコードの選択によって、関税設定タブへ基礎関税や追加関税が渡ります。

### 原産国

国別の税率条件を管理するマスタです。

国名、country、122条、旧相互関税などを持ちます。米国、日本、韓国、ドイツ、EU、マレーシア、タイ、インドネシア、フィリピン、ベトナム、台湾、バングラデシュ、インド、中国、スリランカ、スイスなど、原産国によって税率の扱いが変わる前提を整理しています。

入力シートで原産国を指定すると、関税設定タブの原産国税率に反映されます。

## Data Flow

1. 入力シートで売値、仕入れ、送料、為替、原産国、HTSコード、カテゴリを指定
2. HTSコードタブから品目ごとの基礎関税、301条、232条、免除フラグ、その他追加税率を参照
3. 原産国タブから国別の税率条件を参照
4. 関税設定タブで原産国税率、HTS基礎関税、301条、232条を合成
5. PolicyBands タブで安全側仮関税USDから採用するPolicyBandを決定
6. カテゴリ手数料タブから eBay カテゴリごとの手数料率を参照
7. ロジックタブで売上、販売手数料、決済手数料、Payoneer手数料、両替手数料、関税、MPF、Disbursementを計算
8. 入力シートへ最終利益、利益率、関税内訳、VeRO補正後の利益を表示

この流れによって、入力シートでは少ない項目だけを触りながら、裏側では複数のマスタと計算タブが連動して最終結果を出します。

## Main Features

- eBay US販売向けの利益計算
- USD売値、JPY仕入れ、JPY送料、USD送料の整理
- USDJPY為替を使った円換算
- 州税を含む売上計算
- カテゴリ手数料、決済手数料、Final Value Fee の計算
- Payoneer 手数料と両替手数料の計算
- HTSコード別の基礎関税、301条、232条、その他追加税率の参照
- 原産国別の税率条件の参照
- 関税率の合成
- 安全側仮関税USDとPolicyBandの判定
- MPF、Disbursement、関税+手数料合計の計算
- 関税込み最終利益と利益率の表示
- VeRO補正後の販売額、経費、利益、利益率の比較

## Technical Challenges

- スプレッドシート上で、入力値、参照マスタ、計算ロジック、結果表示を分けること
- HTSコードと原産国の組み合わせで変わる関税率を扱うこと
- 301条、232条、原産国税率、免除フラグ、その他追加税率を合成すること
- USDとJPYが混ざる販売判断を、為替と両替手数料込みで整理すること
- eBayカテゴリ手数料、決済手数料、Payoneer手数料を同じ利益計算に含めること
- 関税、MPF、Disbursementを分けて見せながら、最終的なコストとして合算すること
- 安全側に倒した関税見積もりとPolicyBandの判断を組み込むこと
- 通常販売額とVeRO補正後の販売額を同じ前提で比較できるようにすること
- 複数タブにまたがる参照関係を、日常運用で壊れにくい形に保つこと

## Good Points

- スプレッドシートでありながら、入力、マスタ、計算、結果表示の役割分担がある
- US販売で見落としやすい関税、手数料、為替、送料をまとめて判断できる
- HTSコードと原産国をマスタ化しているため、品目や国が変わっても計算前提を追いやすい
- 関税率の合成を別タブで見られるため、最終利益の根拠を確認しやすい
- PolicyBand を使い、安全側の見積もりを計算フローに入れている
- eBayカテゴリ別の手数料を分けて持たせ、商品カテゴリごとの違いを反映できる
- VeRO補正後の販売額と利益を並べており、出品条件の違いを比較しやすい
- 公開Googleシートとして見せられるため、ポートフォリオ上でも実物の連動構造を確認してもらえる

## Current Value

完成したWebアプリではありませんが、業務整理とロジック設計の価値が見えやすいシートです。

特に、US販売に必要な判断材料を「なんとなく手計算する」のではなく、タブごとに役割を分けて連動させている点が強いです。入力シートだけを見るとシンプルですが、裏側ではHTSコード、原産国、関税設定、PolicyBand、カテゴリ手数料がつながっています。

ポートフォリオでは、スプレッドシートでも業務要件を読み解き、参照設計と計算フローに落とし込めることを伝える作品として扱えます。
